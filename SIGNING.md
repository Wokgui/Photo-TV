# Photo TV signing

Photo TV supports two signing modes.

## Secure release signing

For a private production key, configure these GitHub Actions repository secrets:

- `PHOTO_TV_RELEASE_KEYSTORE_B64`: the complete keystore encoded as one-line Base64.
- `PHOTO_TV_RELEASE_STORE_PASSWORD`: keystore password.
- `PHOTO_TV_RELEASE_KEY_ALIAS`: signing key alias.
- `PHOTO_TV_RELEASE_KEY_PASSWORD`: signing key password.
- `PHOTO_TV_RELEASE_CERT_SHA256` (recommended): expected signing-certificate SHA-256 fingerprint, with or without colons.

When all four required secrets are present, CI builds `assembleRelease`, signs it with that private key, verifies the signature, and labels `signing-mode.txt` as `secure-release`.

The private keystore must never be committed to this repository.

Example local key creation:

```bash
keytool -genkeypair -v \
  -keystore photo-tv-release.jks \
  -alias phototv \
  -keyalg RSA -keysize 4096 \
  -validity 10000
base64 -w0 photo-tv-release.jks > photo-tv-release.jks.b64
keytool -list -v -keystore photo-tv-release.jks -alias phototv
```

Keep the original keystore and both passwords in a durable private backup. Losing the private key prevents future APKs from updating an installed production build.

## Stable development signing

If secure release secrets are absent, CI falls back to the reproducible development signer generated by `tools/generate_stable_signer.py`.

This mode has a stable certificate, so successive development APKs can update one another in place. It is intentionally **not a secure production signer**: its derivation is public because the repository is public. It is suitable for development/update continuity only, not for protecting a public distribution channel.

The expected development certificate SHA-256 is:

`8480f37e2123c7c93ada4dbedef25e0f0f80ec689575c9e75ddc174c43c62d06`

Each APK artifact contains `signing-mode.txt`, which records the signing mode and certificate fingerprint used for that build.
